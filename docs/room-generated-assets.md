# 房间素材创作与布局 skill

MiMo 可以复用家具库，也可以为库外物件创建组合式几何素材。楼梯、局部阁楼平台、护栏、电视、花瓶等不再因缺少固定模型而必须省略。新几何与房间一起保存和导出，收礼端无需再次调用模型。

运行 skill 为 `src/room/agent/composerSkill.ts`，由 `prompt.ts` 注入每次文字/图片请求；照片观察约定在 `referencePrompt.ts`。项目维护 skill 为 [.agents/skills/room-composer/SKILL.md](../.agents/skills/room-composer/SKILL.md)，说明协议和验证入口。

## 几何协议

在原 `version:2` 设计中增加 `assets`，`furniture` 可使用 `type:"custom"`。现有设计继续兼容。

```json
{
  "assets": {
    "simple-vase": {
      "label": "陶瓷花瓶",
      "parts": [
        { "shape": "ellipsoid", "size": [0.2, 0.24, 0.2], "position": [0, 0.12, 0], "color": "#d5b597" },
        { "shape": "cylinder", "size": [0.09, 0.12, 0.09], "position": [0, 0.28, 0], "color": "#d5b597" }
      ]
    }
  },
  "furniture": [
    { "id": "desk-a", "type": "desk", "size": [1.8, 0.76, 0.9], "x": 0, "z": 0, "rotation": 0 },
    { "id": "vase", "type": "custom", "asset": "simple-vase", "parent": "desk-a", "surface": "top", "x": 0.65, "z": 0.2, "rotation": 0 }
  ]
}
```

以上只展示新增字段，其余 palette、lighting 等仍按完整设计协议提供。可执行的完整阁楼例子见 `generatedRoomDesign()`。

- 形体：`box`、`cylinder`、`cone`、`ellipsoid`。尺寸是完整宽/高/深，位置为部件中心，米制。圆柱/圆锥沿局部 y 轴；可选 XYZ Euler 弧度旋转。
- 各部件必须有十六进制颜色，可选材质键用于已有木纹/织物。解析时将整个素材的局部最低点统一到 y=0，不改尺寸、部件间距或旋转；高度最多 5m。保存后的几何必须已使用此原点；实际场景高度仍由落地或真实承托关系决定。
- 每素材 1–64 部件、最多 24 个素材定义、场景所有实例合计最多 384 部件。实例最多 32 件；程序不执行模型提供的代码，也不下载模型提供的链接。
- 承托面使用 `supports:[{id:"deck",part:0}]`，引用真实、水平且未旋转的 box 顶面。宽深从该部件自动计算，四边内缩 2cm，不能声明虚构的空中支撑面。
- 所有高处/桌面物件通过 `parent`、`surface` 绑定；x/z 和朝向相对父级，y 由真实承托面导出。可嵌套，拒绝循环与缺失父级。库内桌柜及参数化书架/衣柜的顶板面名为 `top`（不包含内部架板），自建平台可以使用 `deck` 等名称。
- 窗帘、壁挂素材可用 `mount:{wall:"left"|"back",offset,bottom}` 声明沿墙位置和底部高度，实例的 x/z/rotation 写 0。程序按几何背面推导贴墙坐标与朝向，检查安装接触；整件安装点不能落在空窗洞内。此方式不能与家具 parent 同用。窗台/壁挂花架可通过真实挂墙素材及其承托面组合表达。

## 布局与校验

skill 要求先保留照片的窗墙、主要物件数量、左右/前后关系、上下楼层，再添加细节，保留主要通道。库内模型不合适时生成真实形状，不能给普通桌柜改名冒充电视，也不能套示例布局替代照片。

照片请求只附最小协议例子，不加入整套客厅/阁楼模板，减少布局偏置。书架使用已有层板/书册表现，避免把书架内的书重复生成到柜顶；没有参考依据时不另加沙发、床或地毯。普通台灯复用交互台灯。复杂生成按轮续接，整个任务上限 180 秒、6 次模型调用，同一错误连续失败 3 次停止；每轮最多 170 秒且受剩余总时限约束。界面显示进度并可随时取消，前端累计 190 秒也会退出等待并保留原房间。

程序按自建素材的每个部件做旋转包围盒碰撞检查：楼下沙发可以位于平台空隙内，但仍会碰到立柱；楼上床不能穿过栏杆。桌面电视、花瓶会占用承托空间，纪念物打包时避让这些位置。自建承托面的元数据、物件完整占地、承托高度、落地与场景边界都会检查。相框布局还避开阁楼整体投影，减少被平台遮住的情况。

同一承托面上的小摆件与三件纪念物共同搜索可用位置，避免各自夹到桌边后互相穿插。最多调整八件宽深不超过 1m、高不超过 1.5m 的小摆件，保留原父级、形状、尺寸与朝向，单件平移不超过 0.4m；大件、带承托面结构和其他家具保持。承托检查使用真实底座，上部完整占地仍参与碰撞；上层架板仅在侵入物件所需净高时阻挡下层摆放。位置回写设计，保存/重载与预览一致。搜索最多检查 20,000 个候选位置，不能放下则保留失败，不扩大桌面或删掉摆件。

自建桌面物件由真实底座承托，电视屏幕、花束上部可合理伸出桌面，但完整上部几何仍参与越界及穿插检查。轻微的承托底座越界可在同一承托面内平移最多 0.25m，适配后的坐标写回规范化设计；不能通过这种适配挤入别的物件。贴墙挂件同样参与物件碰撞。

轻微贴墙误差（最多平移 0.4m）可对库内与自建落地实例适配；带 parent 的局部坐标不作墙面修正。随后继续严格校验，不靠删减家具、修改尺寸或任意重排过关。错误会指出物件或窗洞的数值约束，并逐轮反馈给 MiMo 持续修复；新方案通过前保留已有房间，重复错误会要求重新计算并改变局部修正方式。

这是受限基础形体的组合式建模，仍不等同于任意高精度网格、照片测量或完整纹理重建。碰撞检查使用保守的部件包围盒；通路宽度属于设计要求，尚无完整导航/可达性求解器。外壳仍为矩形，主墙真实开口仍使用窗洞协议。避免宣称所有参考都能精确复刻或每次生成都一定成功。

## 验证

`npm test` 包含 `check-room-generated.cjs`：楼梯/平台/电视/花瓶、跨层承托、栏杆碰撞、桌面占位、循环父级、恶意/无效形状、部件预算及保存恢复。模型测试验证实际网格范围与校验一致、父子变换以及几何/材质/纹理仅释放一次。

设置已有 Playwright 的 `NODE_PATH` 后运行 `node scripts/check-room-generated-browser.cjs`，默认使用本地 fixture，验证桌面/手机渲染、相框/信件/CD 交互、保存/刷新与导出。设置 `ROOM_GENERATED_RESULT` 可以重放真实结果，设置 `ROOM_AGENT_LIVE=1` 则实际调用 MiMo，消耗接口额度；结果及截图写入忽略目录 `.room-qa/`。

2026-11-08 已实测：MiMo 生成 7.4 × 4.6 × 6.4m 阁楼房间，自建平台护栏、八级楼梯、电视和花瓶，含一次修正，约 25.5 秒；完整浏览器渲染、交互与保存恢复通过。状态/模型测试、skill 官方格式校验通过。

同日公开参考图的主要布局测试通过：明确要求仅复刻左窗、后方矮书架、右侧边桌和柜顶花束，省略窗帘/窗台植物等次要细节。MiMo 自建白花瓶与花束，含一次修正，约 44.8 秒；重放该真实结果通过桌面/手机渲染、相框/信件/CD 交互与刷新恢复。完整细节一次性复刻测试仍有窗尺寸、承托/物件密度及超时失败，不能将这项通过解释为所有复杂照片都能稳定复刻。

默认保留快速生成模式；服务端可选设置 `MIMO_ROOM_THINKING=enabled`，为照片启用 [MiMo 官方深度思考](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/other/deep-thinking)。该模式等待可能更长；本次复杂照片试验曾超时，因此没有默认打开。只读取最终设计 JSON，不保存或显示推理内容。照片生成仍可能因布局/承托或输出限制而失败，程序会保留旧房间。
