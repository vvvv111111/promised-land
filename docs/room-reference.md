# 房间参考照片

主流程 `/gift/edit` 与独立工作台 `/room-3d` 均支持一张参考照片。上传照片后可直接点击“生成房间”，也可以补充“保留布局，把沙发改成绿色”等要求。纯文字生成继续可用；收礼者不显示上传入口。

这是照片理解驱动的近似搭建：MiMo 观察主要家具、相对布局、窗户、色彩与光线，复用已有家具或生成缺少的几何素材，再经过校验生成可旋转、可点击的 3D 场景。单张照片无法可靠恢复背面、隐藏区域、真实尺度或完整纹理；无法表达的细节与必要布局适配显示在“本次未实现”。新素材与承托协议见 [房间素材创作与布局](room-generated-assets.md)。

## 上传与数据

- 上传格式：JPG / PNG / WebP，单张原文件最多 12MB。
- 浏览器解码后重新编码为 JPEG，最长边不超过 1280px，Data URL 最多 1,600,000 字符。重新编码后的参考不携带原文件的 EXIF/GPS 元数据。
- 选择照片时仅在当前页面准备和预览。点击生成才通过服务端发送给所配置的 MiMo 接口；界面有明确说明。
- 参考照片不写入礼物或本机方案，也不包含在 JSON 导出中，刷新后需重新选择。生成的房间数据、输入类型和照片观察摘要可以保留。
- 礼物相框内的私人照片、信件和音频不会自动作为房间参考发送。参考照片是独立、明确选择的输入。
- 移除参考照片即可继续只用文字生成。上传替换失败保留原先可用的参考，生成失败或取消保留当前房间。

## 接口

`POST /api/room-agent` 支持可选的 `referenceImage`：

```json
{
  "prompt": "保留照片的布局，使用浅木色家具。",
  "referenceImage": "data:image/jpeg;base64,..."
}
```

文字最多 2000 字。照片存在时允许省略文字或传空字符串；没有照片时仍需文字描述。

服务端限制请求体大小，校验 JPEG Data URL、Base64、文件头和尺寸，不下载任意远程图片 URL。MiMo 使用官方 `image_url` + `text` 消息格式；修正重试仍带同一参考。照片被判断为非室内空间时返回 `NOT_A_ROOM`（422），不以示例房间假装识别成功。模型不支持图片或无法处理图片时返回明确错误。

照片生成的米制坐标可能有小幅贴墙误差。程序只校正不超过 0.4m 的墙面间距问题，再执行完整空间校验；不自动改尺寸、增删家具或消除穿插。发生校正时，“生成记录”显示调整数量。柜顶/桌面小摆件可以生成新素材，通过真实 parent/surface 承托放置；不能把它们放成与家具重叠的地面物品。照片中的楼梯、局部阁楼平台、电视等主要物件也优先生成几何，而非因缺少固定模型省略。

返回值仍是 `design`、`definition`、`run`，其中 `run.input` 为 `image`，`run.referenceDescription` 为模型对照片中空间的观察。结果中不包含原图。照片理解约定位于 `src/room/agent/referencePrompt.ts`，作为现有设计协议的补充，避免与模型库或布局协议绑定。

参考：[MiMo 官方图片理解文档](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/multimodal-understanding/image-understanding)。

## 验证

`npm test` 覆盖图片格式/字节/尺寸限制、多模态请求、仅照片与照片加文字、非房间拒绝、修正保留图片和结果不含原图；同时覆盖本地压缩、解码失败和资源释放。

`scripts/check-room-agent-browser.cjs` 覆盖真实文件选择与解码、缩略预览、仅图片生成、补充文字、移除、错误保留、刷新不恢复原图、收礼者无上传入口和手机无溢出。

真实接口检查会使用 MiMo 额度。设置 Playwright 的 `NODE_PATH`、服务地址 `ROOM_URL`、浏览器路径 `ROOM_CHROMIUM` 后运行：

```powershell
node scripts/check-room-agent-image-live.cjs
```

默认只发送项目公开素材 `public/assets/warm-room-v1/room_warm_01.png`。也可显式设置 `ROOM_REFERENCE_FILE` 指定其他参考。检查包括图片上传、真实 MiMo 理解、房间渲染、相框/信件/CD 交互与刷新恢复；结果和桌面/手机截图写入 Git 忽略的 `.room-qa/`。

如已有真实返回结果，可设置 `ROOM_AGENT_REPLAY_FILE=.room-qa/agent-image-live.json` 重放界面检查，不再次使用接口额度。输出会明确区分真实调用与重放。

2026-11-07 已用上述公开素材完成 MiMo 实际图片理解：一次调用返回合法场景，耗时约 16.8 秒。随后重放该真实结果，通过桌面/手机渲染、相框/信件/CD 交互、刷新恢复及原图不持久化检查。状态测试与隔离生产构建通过。另修复了小桌面上纪念物的贪心摆放问题：现在会在有界范围内尝试旋转和缩放组合，仍以完整空间校验为准。
