# 礼物页面 · 已确认实现

## 统一样式

首页、其余七页、独立房间页和相框/信件弹窗沿用暖白背景、低饱和绿色、同一字体家族。去掉深色冬季主题、磨砂玻璃、装饰性标语和页脚。根样式变量在 `src/app/globals.css`；首页样式在 `gift-home.css`，流程样式在 `winter.css`。保留原类名和存储 key，避免无关迁移。

## 页面文案

| 页面 | 标题与说明 | 操作 |
| --- | --- | --- |
| 首页 | 应许之地 / promised land | 制作礼物、打开示例 |
| 制作 | 制作礼物；照片和文字仅保存在此浏览器。 | 返回首页、下一步、重试保存 |
| 准备 | 正在准备 / 准备好了；当前为演示，未使用 AI 生成。 | 进入编辑、返回修改 |
| 编辑 | 编辑礼物；点击相框或信件编辑。 | 修改内容、编辑相框、编辑信件、预览、完成 |
| 完成 | 礼物已完成；分享链接；分享功能尚未开放 | 复制链接（不可用）、预览礼物、返回编辑 |
| 开启 | 送给 {昵称}；来自 {赠送者}；示例礼物（仅示例显示） | 打开水晶球 |
| 探索 | 查看礼物；点击物品，查看照片和信件。；已查看 {数量} / 3 | 返回水晶球、再查看 {数量} 件物品 / 查看回忆 |
| 回忆 | 回忆；只显示回忆、照片、信件和署名 | 返回房间 |

未解锁回忆时显示「查看三件纪念物后，可打开回忆。」和「返回房间」。

制作表单标签：照片、送给谁、你的名字（选填）、共同的回忆、写给对方的话。照片说明为「1–3 张 · JPG / PNG / WebP · 每张不超过 12MB」「第一张用于相框，其余显示在回忆中。」；第一张标记「相框照片」。保存状态为「读取中… / 已保存 / 未保存」。准备步骤为「整理内容、准备房间、放入照片和信件」，状态为「等待中 / 进行中 / 已完成」。

## 房间与弹窗

不显示物品介绍面板和描述；配置字段为兼容原结构保留，不渲染到界面。相框、信件、键盘按钮与收集回调仍有效。用户已取消物品拖动摆放和恢复默认位置入口，镜头操作保留。房间按钮保留小橘、贝壳、相框、信件及背景家具入口，不再包含独立小扶手椅；辅助入口为「用按钮查看物品」。

弹窗标题为「相框 / 信件」；操作为「上传照片 / 更换照片、编辑相框、编辑信件、保存、放弃更改、关闭」；取景为「缩放、左右位置、上下位置」。相框上传仍为 10MB，制作页仍为 12MB，本轮只调整样式和提示，不更改处理规则。正文标签为「正文」，空内容显示「暂无正文」。用户写入的文本不改动；默认示例仅为「这是一段示例回忆。」「这是一封示例信件。」。

## 分享边界

完成页保留独立分享区域，但没有 URL、剪贴板调用或可用复制按钮。真实分享仍需后端持久化与跨设备访问能力，不把 localhost 或本机预览地址当分享链接。预览保持当前浏览器同源行为。

## 验证

- `npm run typecheck`、`npm run build`。
- `check-room-state.cjs`、`check-gift-state.cjs`、`check-placement-state.cjs`：原状态与保存约束。
- `check-winter-routes.cjs`：八页 HTTP、角色规范化、404、主视觉资源。
- `check-gift-flow-browser.cjs`：真实制作、编辑信件与相框取景、完成页不可用分享、收礼只读、三件探索、回忆解锁、保留用户内容和取景，以及桌面/手机八页统一背景、字体、无溢出、无物品介绍和脚本异常。
- 既有四组浏览器测试同步新文案与移除介绍面板后的反馈选择器，保留原有断言语义。相框上传与配额失败、物体拖动/重置/触摸、地板/桌面碰撞/遮挡、JSON 热更新和透明像素命中均通过。

本轮使用临时 Playwright（`.room-qa/browser-deps/`，Git 忽略）与本机 Chrome，未改变项目依赖。截图位于 `.room-qa/unified-<页面>-desktop.png` 和 `mobile.png`，已查看所有页面与代表性弹窗的实际渲染结果。
