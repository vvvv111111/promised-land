# 礼物页面 · 已确认实现

## 统一样式

首页、其余五页、独立房间页和相框/信件弹窗沿用暖白背景、低饱和绿色、同一字体家族。去掉深色冬季主题、磨砂玻璃、装饰性标语和页脚。根样式变量在 `src/app/globals.css`；首页样式在 `gift-home.css`，流程样式在 `winter.css`。保留原类名和存储 key，避免无关迁移。

## 页面文案

| 页面 | 标题与说明 | 操作 |
| --- | --- | --- |
| 首页 | 应许之地 / promised land | 制作礼物、打开示例 |
| 编辑 | 编辑礼物；点击相框或信件编辑。 | 返回首页、编辑相框、编辑信件、CD 机、礼物信息、预览、完成 |
| 完成 | 礼物已完成；解压后可查看，也可上传到静态网站。 | 下载礼物包、预览礼物、返回编辑 |
| 开启 | 送给 {昵称}；来自 {赠送者}；示例礼物（仅示例显示） | 打开水晶球 |
| 探索 | 查看礼物；点击物品，查看照片和信件。；已查看 {数量} / 3 | 返回水晶球、再查看 {数量} 件物品 / 查看回忆 |
| 回忆 | 回忆；只显示回忆、照片、信件和署名 | 返回房间 |

未解锁回忆时显示「查看三件纪念物后，可打开回忆。」和「返回房间」。

“制作礼物”直接进入编辑器，旧 `/gift/create` 与 `/gift/generating` 地址跳转到同一编辑页并保留有效礼物 ID。照片、信件和音乐只保留场景内编辑入口；昵称与回忆在同页折叠区“礼物信息”中填写，标签为“送给谁、你的名字（选填）、共同的回忆”，点击“保存信息”提交。保存合并最新场景和内容，不覆盖其他字段；冲突或失败保留输入，未保存时阻止预览、完成和返回首页。旧礼物的额外照片继续保留。

## 房间与弹窗

不显示物品介绍面板和描述；配置字段为兼容原结构保留，不渲染到界面。相框、信件、键盘按钮与收集回调仍有效。用户已取消物品拖动摆放和恢复默认位置入口，镜头操作保留。房间按钮保留小橘、贝壳、相框、信件及背景家具入口，不再包含独立小扶手椅；辅助入口为「用按钮查看物品」。

弹窗标题为「相框 / 信件」；操作为「上传照片 / 更换照片、编辑相框、编辑信件、保存、放弃更改、关闭」；取景为「缩放、左右位置、上下位置」。相框上传限制仍为 10MB。正文标签为「正文」，空内容显示「暂无正文」。用户写入的文本不改动；默认示例仅为「这是一段示例回忆。」「这是一封示例信件。」。

## 分享边界

完成页下载独立只读静态礼物包，完整包含房间、宠物、照片、信件和可选音乐；可解压查看或手动上传托管。没有自动上传云端、公网 URL 或剪贴板调用。预览保持当前浏览器同源行为。实现与限制见 [打包 Agent](gift-publish-agent.md)。

## 验证

- `npm run typecheck`、`npm run build`。
- `check-room-state.cjs`、`check-gift-state.cjs`、`check-placement-state.cjs`：原状态与保存约束。
- `check-winter-routes.cjs`：六页 HTTP、旧入口跳转、角色规范化、404、主视觉资源。
- `check-gift-flow-browser.cjs`：直接进入编辑器、礼物信息保存与未保存阻拦、编辑信件与相框取景、完成页打包入口、收礼只读、三件探索、回忆解锁，以及桌面/手机六页统一背景、字体、无溢出和脚本异常。
- 既有四组浏览器测试同步新文案与移除介绍面板后的反馈选择器，保留原有断言语义。相框上传与配额失败、物体拖动/重置/触摸、地板/桌面碰撞/遮挡、JSON 热更新和透明像素命中均通过。

本轮使用临时 Playwright（`.room-qa/browser-deps/`，Git 忽略）与本机 Chrome，未改变项目依赖。截图位于 `.room-qa/unified-<页面>-desktop.png` 和 `mobile.png`，已查看所有页面与代表性弹窗的实际渲染结果。
