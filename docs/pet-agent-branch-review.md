## 有价值的增量

分支的 `tools/pet-recognition-generation/agent.py` 新增两项能力：

1. `REGIONAL_PRESETS`：`bicolor_white` 表达白脸、白胸腹、白腿与棕色肩背/后臀斑块；`saddle_white` 表达棕头耳、黑背鞍、白胸白腿及预设白尾尖。这比随机 `patches` 更能控制毛色所在的身体区域。
2. `regional_presets()` 与 `recognition_prompt()`：同时检查素材库清单、运行时标记与遮罩文件，只有本机实际启用的预设才加入识图提示词；照片特征不符或关键区域不可见时回到普通花纹。生成时校验物种与主辅色，并在结果记录 `regional_preset`。

建议未来按“能力检测 → 提示词 → 参数校验 → 渲染 → 资产元数据”的路径引入这些能力。只移植这部分逻辑，不整分支覆盖，也不复制另一份独立 Agent 目录。

## 当前不能直接启用的原因

- 分支只提交 Agent 调用逻辑，没有 `PetStudio/server.py`、`storage.py`、`web/regional-masks.mjs`，也没有 `Pet_Visual_Library/library_manifest.json` 或主模板资产。当前提供的四款 GLB 素材包也不含这些文件。
- `render.py` 与当前版本逐字相同（忽略换行）；渲染器本身没有新增分区着色功能，真正的绘制依赖外部 PetStudio。
- 当前四款备选保留原毛色，这些预设适用于原主模板，不能只改识图提示词就给四款备选重新着色。
- 分支把 PetStudio 作为必需依赖，而当前版本已支持缺少主模板时仅匹配备选。还需保留当前的 API 地址配置、非交互密钥处理、临时输出目录、轻量模型、取消/超时、尺寸合并与浏览器保存能力。

## 集成时还应补足

- 新预设要求 `server.validate()` 与 `window.petStudio.apply()` 同时支持，不能只靠清单声明。应增加版本/能力检查和实际渲染测试。
- 分支给出的固定 `scale=1`、`amount=0.5`、`seed=0` 目前只在提示词中声明；移植时应在受控参数层明确校验，避免把依赖是否支持建立在模型遵守提示词上。
- 当前 Web 服务返回结构与 `PetAsset` 尚未传递 `regional_preset`、外观参数及映射损失。接入主模板时应将必要来源与近似信息随资产保存和导出，视觉恢复仍以完整 GLB 为准。
- 当前主模板输出也受 2.5MB 模型预算约束；现有轻量化脚本专用于静态模型，拒绝蒙皮/动画模型。主模板导出需要单独验证体积和蒙皮兼容性。
