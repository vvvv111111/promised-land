# 冬日音乐水晶球：实现与验收记录

## 启动与路由

运行 `npm run dev`，访问 http://localhost:3000。原有 `/world-demo` 仍可独立使用。

| 页面 | 路由 | 主要行为 |
| --- | --- | --- |
| 首页 | `/` | 创造礼物、示例礼物、音乐控制 |
| 创造礼物 | `/gift/create` | 1–3 张照片、昵称、回忆、信件，本地草稿 |
| 模拟创造 | `/gift/generating` | 三阶段模拟状态，手动进入编辑 |
| 编辑礼物 | `/gift/edit` | 规范化为 sender；原有房间、相框、信件、摆放、预览 |
| 完成与分享 | `/gift/complete` | 复制本机预览链接、预览、返回编辑 |
| 开启礼物 | `/gift/open` | 水晶球、赠送者与欢迎语、开启 |
| 探索房间 | `/gift/room` | 规范化为 recipient；物件探索、三件进度、音乐 |
| 最终故事 | `/gift/story` | 集齐三件后展示回忆、照片和信件，支持返回 |

`room` 和 `edit` 路由由服务端固定 mode 与 gift 参数，避免收礼页缺少参数后落入房间默认赠送者模式。此处是本地 Demo 界面权限，没有真实鉴权服务。

## 数据与兼容边界

- `promised-land:gift:winter-local-v1` 是礼物的唯一保存来源。GiftStore 的完整对象包含相框、信件与 `details`（人物、回忆、额外照片）；第一张照片仅存在相框内容中。表单草稿是该对象的页面内编辑状态。
- `promised-land:winter:draft:v1` 仅兼容读取，不再写入。旧正式相框与信件优先，旧草稿只补缺失资料；已有 `details` 时完全忽略旧草稿。初始化不写存储，下一次成功保存时将兼容读取结果完整写入正式对象。
- `promised-land:winter:collection:v1` 保存外层三件收集进度。
- 位置继续使用现有 RoomLayout 存储。没有更改任何旧 key 或队友文件。
- RoomBridge 通过 WorldDemo 的 `onReady` / `onError` 控制编辑按钮，通过 `onItemCollected(itemId)` 更新收集进度。WorldDemo 另提供 `onObjectClicked(objectId)` 回调。编辑按钮调用 ref 上的 `onEditRequest(objectId)`，无需观察 DOM、匹配中文文字或模拟按钮点击。画布和键盘探索按钮沿用同一个交互出口。
- 上传在浏览器压缩为最长边 900px 的 JPEG；格式、大小、数量验证，预览与删除，失败提示与保存重试。
- 音乐为 Web Audio 本地合成旋律，用户主动开启，支持暂停和卸载清理，不是已接入的第三方音乐素材。
- 生成进度、房间选择、纪念物与故事布局为模拟/固定模板。回忆、信件和照片来自本机输入。链接仅同浏览器同源预览，不能跨设备传递内容。

## 本次稳定性修复与人工验收

表单保存先组合完整礼物，再由 `GiftStore.saveGift` 校验并执行一次 `setItem`。只有写入成功后才替换 Store 内存；失败保留原完整对象，页面保留未保存输入供现有重试按钮使用。房间弹窗保留 `save(objectId, content)` 操作接口，内部同样提交完整对象并保留人物、回忆与额外照片。取景仅在首张照片实际替换时重置。

`scripts/check-gift-state.cjs` 补充验证整对象单次写入、失败后内存与存储不变、刷新恢复、旧草稿只读兼容、正式数据优先、房间/表单一致及取景保留。人工需核对：制作与刷新、房间修改后预览、存储失败后重试、外层两个编辑按钮、画布/键盘探索计数与故事解锁。未改变八页流程、CSS、素材、Phaser 场景或摆放算法。

本次检查：TypeScript、生产构建、room/gift/placement 状态脚本与 winter HTTP 路由脚本通过。四个既有浏览器脚本均已尝试，因 `Cannot find module 'playwright'` 未能启动；离线临时依赖安装也因缓存不完整失败，未修改项目依赖。回调与编辑入口的真实浏览器操作仍待人工验收。多标签页并发覆盖、两套照片压缩参数、多礼物隔离与服务端分享不属于本次修复。
