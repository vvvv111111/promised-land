# 应许之地 Promised Land

**基于 Xiaomi MiMo 的个性化互动数字礼物：把照片、宠物形象和共同回忆放进一个可探索的 3D 空间。**

## 一、我们解决什么问题？

- **定制成本高**：依赖人工设计、素材制作和反复沟通，制作周期较长。
- **制作门槛高**：普通用户难以自行完成三维建模、空间设计和交互开发。
- **情感内容分散**：照片、文字和音乐缺少统一的承载方式，难以形成完整的礼物体验。

## 二、项目背景

### 1. MiMo 核心能力：从 Vibe Coding 到 Vibe World

MiMo 官方提出 **Vibe World**：通过多模态感知、3D 空间推理与多智能体协作，将用户需求转化为可运行的交互世界。[官方介绍](https://mimo.mi.com/docs/zh-CN/news/latest/v2-6)

应许之地将这一方向应用于数字礼物，重点体现：

- **理解真实素材**：结合照片和文字，识别房间布局、家具、配色与宠物外观。
- **规划三维空间**：将需求转化为物件组合、尺寸、位置和光照方案。
- **生成并修正结果**：输出结构化设计，根据校验反馈调整，由程序构建可探索、可交付的空间。

### 2. 应用场景

- **宠物纪念**：保留宠物形象与陪伴记忆。
- **生日赠礼**：将照片、信件和音乐制作成专属礼物。
- **情侣与家庭纪念**：通过熟悉的空间与纪念物，呈现共同生活的回忆。

## 三、产品如何使用？

### 1. 制作礼物

- **生成房间**：输入文字或上传参考照片，生成近似布局、家具和配色。
- **定制宠物**：上传猫狗照片，基于基础模型生成近似毛色和花纹。
- **添加回忆**：在相框、信件和 CD 机中添加照片、文字、音乐或已有录音。
- **确认保存**：查看组合预览，确认后保存为正式礼物。

### 2. 探索礼物

- 打开水晶球，旋转、缩放视角，点击物品查看特写。
- 查看照片、阅读信件、播放音乐、开关台灯。
- 查看三件纪念物后，解锁最终回忆。

### 3. 交付礼物

- 下载包含场景、模型和媒体的独立 ZIP 礼物包。
- 解压后用支持 WebGL 2 的现代浏览器查看，或手动上传静态托管后分享。
- 收礼查看无需再次调用 MiMo，也不依赖制作端的本地存储。

## 四、真实技术与 Agent 协作

### 1. 技术栈

| 类别 | 实际使用的技术 | 主要职责 |
| --- | --- | --- |
| 应用框架 | Next.js、React、TypeScript | 页面、编辑器与服务端接口 |
| 大模型 | Xiaomi MiMo，默认配置 `mimo-v2.6-pro` | 房间规划、错误修复、宠物外观识别与对照 |
| 三维引擎 | Three.js / WebGL | 参数化建模、灯光、镜头和点击交互 |
| 场景约束 | 自定义 JSON 协议、空间校验算法 | 检查边界、碰撞、承托与窗户避让 |
| 宠物生成 | Python、Chrome、PetStudio | 模板处理、毛色绘制、贴图烘焙与 GLB 导出 |
| 本地存储 | localStorage、IndexedDB、Web Locks | 保存礼物与二进制资产，处理保存冲突 |
| 独立交付 | esbuild、fflate | 构建查看器、生成 ZIP |

### 2. 任务分工

- **房间 Agent**：需求／参考照片 → MiMo 输出设计数据 → 几何校验与有限修复 → 场景构建。
- **宠物 Agent**：宠物照片 → MiMo 提取外观 → 模板毛色生成 → 渲染对照与有限修正 → GLB。
- **编辑器编排**：两项任务可并行运行，完成后合入最新预览；程序统一宠物尺寸并检查落地、避碰。

### 3. 关键实现

- **受约束生成**：程序根据结构化数据构建场景，库外物件可用基础形体组合。
- **结果可修复**：将具体布局错误反馈给模型；简单修改支持局部补丁。
- **保存可恢复**：预览与正式保存分离，支持取消、冲突提示和失败重试。

## 五、当前成果与边界

### 已完成

- **制作流程贯通**：生成、编辑、预览、保存、收礼探索和打包已形成原型。
- **已有验证**：类型检查、状态与模型检查、生产构建、Playwright 桌面和手机回归；开发记录包含真实 MiMo 调用。

### 尚未实现

- **精确还原**：房间和宠物均为近似生成，受照片信息、模板形体和生成质量限制。
- **宠物动态**：当前静态展示，尚无动画、自主行走和点击反馈。
- **在线商业服务**：尚无账户、服务端数据库、支付、自动发布与跨设备同步；导出包没有访问鉴权。

## 六、产品规划

**从室内房间出发，拓展以现实世界为参考的多样环境，打造丰富的可交付场景。**

### 1. 扩展场景类型

| 场景类别 | 规划方向 |
| --- | --- |
| 生活空间 | 卧室、客厅、庭院、阳台、咖啡馆 |
| 自然环境 | 海边、沙滩、森林、草地、湖畔、山间 |
| 记忆地点 | 校园、街巷、旅行目的地及具有个人意义的地点 |

### 2. 丰富定制与互动

- **场景氛围**：逐步支持日出、黄昏、季节、天气和环境音。
- **宠物表现**：扩展品种与体型，提高外观还原程度，加入动作、点击反馈与自主移动。
- **回忆探索**：让照片、信件和纪念物融入不同环境，丰富内容发现方式。

### 3. 建立可交付场景库

- **场景模板**：积累可复用的环境、素材和交互组件，支持快速定制。
- **质量与交付**：统一视觉检查、交互验证和打包流程，提高交付稳定性。
- **持续更新**：逐步支持在已有空间中添加照片、故事与新的纪念内容。

## 七、未来落地规划

**经营目标：探索由一名创始人统筹、多个专业 AI Agent 协作的 OPC（One Person Company）模式。以下均为后续规划。**

### 1. 建立交易与交付基础

- 衔接账户、下单、支付、订单记录和在线交付。
- 标准化需求收集、制作验收、修改与售后流程。
- 建立任务日志、成本记录和人工接管机制。

### 2. 让 Agent 参与经营

| 环节 | 规划职责 |
| --- | --- |
| 市场运营 | 需求研究、内容策划与推广辅助 |
| 客户管理 | 咨询整理、定制需求收集与反馈跟进 |
| 生产交付 | 订单转任务、生成调度、质量检查与打包 |
| 经营分析 | 汇总订单、转化、任务表现和模型成本 |

**创始人职责**：方向判断、定价、关键决策、质量把关和异常处理。

### 3. 用真实订单验证效率

- **开展试运营**：获取首批用户、付费订单和实际反馈。
- **跟踪指标**：成功率、交付时间、修改次数、满意度、人工介入、Token 与基础设施成本。
- **评估价值**：在同等交付质量下对比人工流程，验证效率、成本与可复制性，再优化定价和分工。
